# `RFC_READ_TABLE`: any table over RFC, 512 characters at a time

**Level:** 201 · for anyone whose extraction tool "connects to SAP" and who wants to know what that means

**One line:** `RFC_READ_TABLE` reads any transparent table for a remote caller and returns the rows as text in a 512-character buffer, with the fields it chose described by offset and length in a second table and the `WHERE` clause supplied as 72-character lines in a third; every limit of the tools built on it, the row too wide, the page that overlaps, the clause that fails at a line break, is one of those three tables, and since the extension its own source comments name, the table asked for is also checked against an allow-list the administrator keeps in `SLDW`.

   VALUE(USE_ET_DATA_4_RETURN) TYPE BOOLE_D OPTIONAL
EXPORTING
   VALUE(ET_DATA) TYPE SDTI_RESULT_TAB
TABLES
   OPTIONS STRUCTURE RFC_DB_OPT OPTIONAL
   FIELDS STRUCTURE RFC_DB_FLD OPTIONAL
   DATA STRUCTURE TAB512 OPTIONAL
EXCEPTIONS
   TABLE_NOT_AVAILABLE  TABLE_WITHOUT_DATA  OPTION_NOT_VALID
   FIELD_NOT_VALID  NOT_AUTHORIZED  DATA_BUFFER_EXCEEDED

and, below it, a comment that the logic was extended with SAP Note 2246160 and now checks the table name against the system access rule `RFC_READ_TABLE_TABL` maintained in transaction `SLDW`.

## The interface, parameter by parameter

| Parameter | What it does | How sure |
| :-- | :-- | :-- |
| `QUERY_TABLE` | The table or view to read. Anything the Dictionary knows and the caller is authorized for. | sure |
| `DELIMITER` | One character written between the fields of each returned row; space means none, and the fields sit at fixed offsets. | sure |
| `NO_DATA` | Anything but space: return only the field catalogue in `FIELDS`, no rows. The cheap way to learn a table's layout. | sure |
| `ROWSKIPS`, `ROWCOUNT` | Skip the first n rows, return at most m: the paging every connector uses. | sure |
| `GET_SORTED` | Sort by the primary key, which is what makes two pages of the same query consistent. Added by the extension. | fairly sure on the sort key |
| `USE_ET_DATA_4_RETURN`, `ET_DATA` | Return the rows in `ET_DATA`, a table of strings, instead of `DATA`; a string has no 512-character limit. Added by the extension. | fairly sure |
| `FIELDS` | In: the fields wanted, empty for all. Out: for each, its name, offset in the row, length and type. | sure |
| `OPTIONS` | The `WHERE` clause, one line of up to 72 characters per row, concatenated before the `SELECT`. | sure |
| `DATA` | The rows, one per line, in a field `WA` of 512 characters. | sure |
| `DATA_BUFFER_EXCEEDED` | The requested fields do not fit in 512 characters. | sure |
| `OPTION_NOT_VALID`, `FIELD_NOT_VALID` | The concatenated `WHERE` clause does not parse; a field is not in the table. | sure |
| `NOT_AUTHORIZED` | The caller lacks the table authorization, or the table is not in the allow-list. | sure |

   DATA: []

   DATA_BUFFER_EXCEEDED: the row would be 540 characters, the buffer holds 512
   the way out is the FIELDS table: ask for fewer fields per call, and join the calls by key
   ['TEXT01', 'TEXT02', 'TEXT03', 'TEXT04', 'TEXT05'] -> 300 characters: fits

## Who calls it, and why it is a security topic

`RFC_READ_TABLE` is the function behind most generic "SAP table" connectors: BI and ETL tools, data-integration platforms, and scripts on the SAP RFC SDK (the Python binding is `pyrfc`). SAP's own tools ship variants with wider buffers in their own namespaces, and some third-party tools install theirs. The appeal is that one function reads every table with no development in SAP; the cost is everything a table lacks and a view has:

- **No semantics.** Raw table text: no conversion exits (the partner number comes with its leading zeros, a date as `00000000`), no texts, no currency shift, no joins. Everything the [CDS view](../cds_view_annotations/README.md) adds is absent.
- **No delta.** Every call is a full read of what the clause selects. A caller that wants changes keeps the last load and compares.
- **Authorization at table level only.** The check is the table authorization (`S_TABU_DIS` by authorization group, `S_TABU_NAM` by table name) and the RFC authorization for the function group, nothing about the rows: a user who may read `BUT0ID` reads every partner's identification numbers. Tables of password hashes, salaries and bank details are tables too, which is why the allow-list exists: with the rule `RFC_READ_TABLE_TABL` active in `SLDW`, a table not on the list is refused whatever the caller's table authorization.
- **Performance by accident.** A clause with no selective condition reads the whole table on the database and ships it in pages; the database sees one `SELECT` per page, and without the sort each page may be a different subset.

## Where S/4HANA differs

In S/4HANA Cloud there is no `RFC_READ_TABLE` for customers; data leaves through released APIs and released CDS views, which is the chapter's other two pages. On premise the function remains, with the allow-list check, and the released alternatives are the ones to prefer: an extraction view with delta for a warehouse, an OData API for an application, a BAPI or a released RFC module for a transaction.

## Po polsku, w skrócie

`RFC_READ_TABLE` czyta dowolną tabelę przez RFC i zwraca wiersze jako tekst w buforze 512 znaków; pola opisuje druga tabela (nazwa, przesunięcie, długość), a warunek `WHERE` podaje się trzecią, w liniach po 72 znaki. Każde ograniczenie narzędzi zbudowanych na tej funkcji to jedna z tych trzech tabel: zbyt szeroki wiersz, niestabilna strona bez sortowania, warunek przerwany w złym miejscu. Funkcja nie ma semantyki, delty ani uprawnień na poziomie wierszy, dlatego administrator ogranicza ją listą dozwolonych tabel w `SLDW`, a lepszą drogą są widoki CDS z ekstrakcją i serwisy OData.

## Auf Deutsch: Stichwörter

`RFC_READ_TABLE` liefert jede Tabelle als Text in einem Puffer von 512 Zeichen, mit Feldkatalog und WHERE-Klausel in zwei weiteren Tabellen; die Grenzen der darauf gebauten Werkzeuge sind die Grenzen dieser drei Tabellen.

Stichwörter: Funktionsbaustein · Feldkatalog · Offset und Länge · Trennzeichen · Zeilenpuffer · Paging · Sortierung · WHERE-Klausel in 72 Zeichen · Berechtigung auf Tabellenebene · Positivliste · kein Delta.
